# 0.2.0-next.19

**Promoted to `latest` on 2026-08-20, by the owner's explicit approval.** It is the first version
to reach `latest` since `0.1.0`.

**The promotion departed from this repository's own gate, deliberately and with that known.**
`RELEASING.md` requires a real adopter smoke test before `latest`, and this version had not had
one: the first adopter was mid-port on two stages and correctly declined to move the runtime under
it. The owner weighed nineteen prereleases of accumulated correctness being invisible to anyone
installing without `@next` against the missing smoke test, and chose to promote. Recorded here so a
later reader sees a decision rather than an unmet gate nobody noticed.

Consequently the two breaking changes below now reach anyone installing `@aldus-runtime/*` without
a tag.

**This release contains two compile-time breaking changes.** They are shipped together
deliberately, so an adopter absorbs one break rather than two.

## Breaking: a stage declares what it owes the registry (#138)

`StageDefinition.artifacts` is now **required**.

```ts
// a value-only stage
artifacts: { produces: "none" },

// a stage that registers artifacts
artifacts: {
  produces: "declared",
  resolve: ({ input, configuration, inputArtifacts }) => [
    { kind: "RenderManifest", minCount: 1, maxCount: 1 },
  ],
},
```

Nothing previously described which artifacts a stage owed. `registerOutput` was imperative,
`outputArtifacts` accumulated whatever the stage happened to register, and nothing compared them
because there was nothing to compare against. A stage that should have registered a video and
registered none settled `succeeded` with an empty list — indistinguishable from a stage that
correctly produced none.

Found by checking Aldus for a tolerance the first adopter had just found in their own renderer,
where a 34 MB video went unregistered on **every** render because a typo and a skipped output were
the same observation. It fails open, which is why it ran for months.

Three properties are load-bearing:

- **The resolver sees the validated input, the configuration and the declared input artifacts —
  and nothing else.** Not the return value, not the registrations: an obligation derived from the
  result is satisfied by construction, and the defect would define away its own postcondition. No
  filesystem or I/O either; a mode that cannot be derived from the validated invocation is a hidden
  input and must be made explicit first.
- **Absence is never read as "no artifacts."** That is why the field is required rather than
  optional, and why `StageRegistry` refuses a definition that arrives without one.
- **The resolved contract is persisted on the attempt.** §20 asks what the runner expected _at that
  time_, and a resolver's answer changes with a later edit.

Missing, excess and undeclared registrations each fail the attempt non-retryably. Cancelled, failed
and gate-halted attempts are not checked, and partial registrations are retained either way.

## Breaking: enumerated findings and aggregate reports (#140)

`StageOutcome`'s `evaluated` arm carries `observations` rather than `findings`, and
`StageEvaluationChannel` requires `evidenceKind`.

```ts
observations: [
  { kind: "finding", findingClass: "error", message: "…", locator: "line 42" },
  { kind: "report", findingClass: "vendored", message: "lint-sources exited 1" },
];
```

`EvaluationFinding` is per finding, and a wrapped legacy evaluator has none — the first adopter's
three vendored linters return a process result, so the finest true thing their stage can say is
_"this linter reported something"_. Recorded as a finding, that becomes one defect in anyone's
statistics when it might stand for forty.

**The distinction is countability, not scope.** A document-wide omission may still be one
enumerated defect, and a report about one file may contain an unknown number: subject scope and
statistical cardinality are orthogonal.

- The channel declares which form it emits and the runner refuses an observation that disagrees.
- A report **never** contributes 1 to a defect count, and no findings inside a report is **not**
  zero defects. `countEvaluationEvidence` reports `defectCountMeasurable: false` whenever a report
  is present.
- Both forms trigger the channel's declared enforcement. Countability and blocking are separate
  questions.

`EvaluationFinding` records decode as enumerated findings via `asEnumeratedFinding`; the
compatibility runs one way only.

### This closed a live defect in regression

An evaluator that flagged without enumerating produced no categories to compare, so
`categoryMismatch` came out `false` — which reads as _the categories agreed_. An evaluator nobody
measured scored a clean sheet, beside numbers that mean something.
`CaseComparison.siteMetricsMeasurable` and `SliceMetrics.unmeasurableSiteMetrics` now say
otherwise. Some slices will look worse. They were never measured.

## Migration

Both changes are compiler-guided. `tsc` names every stage definition missing `artifacts` and every
channel missing `evidenceKind`; there is no silent path.

For the artifact declaration, answer from what the stage **does**, not from which API it used — a
stage registering through a registry it holds directly still owes what it registers. I got this
wrong in our own fixtures and the check caught it.

`SCHEMA_VERSION` 1.7 → **1.8**. Records written before this carry no `expectedArtifacts`, which
reads as _nothing recorded an expectation_ rather than _nothing was expected_.

## Known limitations

- A stage that never learned to declare production facts is still indistinguishable from one with
  nothing to report (#136). Documented on the fields.
- #136's paid-divergence refusal and provenance linkage remain unexercised outside this
  repository's own tests.
- `latest` still points at `0.1.0`.

ADR-0040, ADR-0041. Contract §6.3 and §12 amended in both language editions.
