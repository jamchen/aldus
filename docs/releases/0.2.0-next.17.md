# 0.2.0-next.17

A prerelease on the `next` dist-tag. **Not promoted to `latest`** — `latest` stays where the last
deliberate promotion left it (ADR-0023), and promotion is the owner's decision.

## An evaluator reports findings instead of throwing (#115)

`StageOutcome` was `completed` or `gate_required`, so a Stage running an evaluator had exactly one
way to report a defect: throw. That made two different events arrive identically. An evaluator
whose parser crashed and an evaluator that ran cleanly and found an unsupported claim were both
`status: "failed"`, `ALDUS_STAGE_EXECUTION_FAILED`, category `internal`.

The asymmetry is why it persists rather than getting noticed. A crash indistinguishable from a
finding fails **open** — the evaluator is believed to have run. The reverse fails closed and loudly
and gets fixed the same day. The first adopter had a checker crash on every run for the length of a
migration, counted the whole time as a soft finding.

```ts
| { kind: "evaluated"; output: O; findings: readonly EvaluationFinding[] }
```

- A blocking finding settles as `ALDUS_STAGE_EVALUATION_BLOCKED`, category `policy`. A thrown
  evaluator keeps `ALDUS_STAGE_EXECUTION_FAILED`, category `internal`. The trace tells them apart.
- **Blocking is decided by the declared channel for the finding's class, never by the Stage.** This
  also closes the route around §12.1: a model-assisted channel that could not be declared blocking
  without calibration evidence must not become blocking by throwing instead.
- **An undeclared finding class is refused, not defaulted.** Defaulting to advisory discards a
  finding the adopter believed blocking; defaulting to blocking stops Runs on a class nobody
  reviewed.
- **Advisory findings are recorded.** This needed a real fix: attempt notes were captured before
  the outcome was handled, so anything appended during evaluation was dropped — leaving a green
  record, which §12 says never means semantic correctness.

`EvaluationFinding` is exported from `@aldus-runtime/stage-runner`. Because it is type-only, the
value-level published-surface check could not see it; a compile-time assertion was added, which is
#121's lesson applied one release later.

Contract §12 amended (both language editions). ADR-0037.

## Migration

None. `completed` is unchanged, and a Stage that throws on a finding behaves exactly as it did —
worse, but not differently.

## Known limitations

- **#133** — whether `SynthesisOutcome` gains an optional observed-parameters field is an open
  owner decision.
- **#111** — the Worker seam awaits the first adopter's acceptance run, which is correctly blocked
  on their own human gate.
- `latest` still points at `0.1.0`. Every `0.2.0-next.*` change above is unavailable to anyone
