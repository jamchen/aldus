# Release report — Aldus 0.1.0

Bootstrap public preview. Published 2026-08-18 to the public npm registry under the
`@aldus-runtime` scope.

**This release has not been validated by a real adopter.** Megaphone's 月辯／紅眼 integration is
the intended first validation. Nothing has been announced.

## Verification performed after publishing

- All twelve versions present at `0.1.0`, one version each.
- Every published tarball byte-identical to the pre-publish set (`sha512` integrity match).
- `Apache-2.0` recorded on all twelve.
- Every internal dependency pinned to exactly `0.1.0`.
- External dependency surface: `zod@^4.4.3` and `@types/node@^26.2.0`, both MIT.
- Clean install from the registry into a project outside the monorepo: 12 packages resolved,
  nothing resolving into the workspace, `aldus --help` runs, public API imports.

Registry propagation lagged by several minutes for eleven of the twelve packages. A verification
step running immediately after publish would see spurious 404s.

## dist-tags — a documented deviation

Both `latest` and `next` point at `0.1.0` on all twelve packages, although every publish
specified `--tag next`.

npm assigns `latest` on a package's **first** publish regardless of the flag, because a package
must have one. The state was accepted rather than repaired: removing `latest` would make
unversioned installation confusing or unavailable without materially reducing exposure, and
removing it inconsistently would be worse than the condition.

Recorded in [ADR-0023](../adr/0023-bootstrap-release-exception.md). Future unvalidated releases
use prerelease versions (`0.2.0-next.0`), which npm will not move `latest` to, and the release
workflow now asserts tag movement around every publish.
