# 0.2.0-next.20

A prerelease on the `next` dist-tag. **Not promoted to `latest`** — promotion is the owner's
decision (ADR-0023).

**Contains a correctness fix whose urgency is diluted by shipping beside a breaking change.** Read
the note under #150 before deciding when to take it.

## An unknown amount is billing evidence, not a missing one (#150)

```
observation { billingStatus: "unknown" }   ACCEPTED
the same object as a CostRecord            REFUSED
```

`.pick()` does not carry refinements, so `costObservationSchema` accepted what `costRecordSchema`
refused. The honest observation — _the provider charged us and did not say how much_ — was **valid
to report and fatal to append**: the service threw, and the caller lost the cost record, the event
**and** the completed `AgentResult`, after the money was gone.

- One shared invariant, applied to both compositions: an amount, or a statement that the amount is
  unknown. **No fabricated zero** — zero is a numerical assertion and an unknown amount is an
  uncertainty state.
- `SpendLedger` gains `unresolvedUnknown` and `remainingIsDeterminate`. `checkSpend` refuses with
  `billing-unconfirmed` while one stands, **before** the arithmetic, because the arithmetic is what
  cannot be trusted. An estimate does not resolve it.
- `CostSummary` gains `unknownBillingRecordCount` and `unquantifiedUnknownBillingRecordCount`. An
  amount-less charge has no currency to derive, so `currenciesWithUnknownBilling` cannot represent
  it — and a reader relying on that field alone would see an empty list and read it as _no
  unconfirmed billing_.

**On urgency.** This fixes a failure that happens _after_ an external effect, so it is more serious
than an ordinary validation problem. It ships here beside two compile-time breaks, which means
taking it requires the migration below. If that is the wrong trade for you, say so — the fix is
separable and could be backported.

## Breaking: an effect key belongs to the effect (#148, #149)

`idempotencyKey: effectKey ?? invocationKey` cited ADR-0036 while doing what ADR-0036 forbids in as
many words, and because both values are computed once per attempt, **every Worker invocation in an
attempt received the same key**. For a stage with an empty input schema and no declared artifacts
that key is a _constant_ — so a platform deduplicating on it would treat every episode's first
request as a repeat of the first episode's, forever.

- `WorkerRequest.idempotencyKey` is now **optional and absent** when no effect-specific key exists.
  Never `runId`, `attemptId`, a configuration digest, or an empty input-hash set.
- `StageIdempotency` → `StageRetrySafety`; the field `idempotency` → `retrySafety`. Four arms named
  for what they claim, because `idempotent` read as a property of the computation and was taken as
  one — a stage uploading to a cloud drive declared it.
- `StageWorkerRequest.effect` is required. An effectful invocation carries its own key.
- Enforced **before** the Worker is reached: a pure stage may not perform an effect, an empty key is
  refused, and a stage-scoped key is refused the moment it would cover a second effect.
- The declaration and its reason are on the attempt, so the retry decision reads them rather than
  filing them for an audit nobody performs.

### Migration

```ts
// before
idempotency: { kind: "idempotent" }
idempotency: { kind: "idempotent_external_effect", effectKey }
idempotency: { kind: "not_idempotent", reason }

// after
retrySafety: { kind: "no_external_effects" }
retrySafety: { kind: "deduplicated_external_effects", keyScope: "stage", effectKey }
retrySafety: { kind: "not_idempotent", reason }

// new, for a stage whose effects are N and individually deduplicated
retrySafety: { kind: "deduplicated_external_effects", keyScope: "worker_invocation", reason }

// every runWorker call now declares its effect
context.runWorker({ workerId, workerVersion, input, effect: { kind: "none" } })
context.runWorker({ …, effect: { kind: "deduplicated", idempotencyKey: `archive-${digest}` } })
```

Compiler-guided throughout; there is no silent path on either change.

## Corrections to earlier releases

- **ADR-0041 recorded an argument against parsing evaluator output too broadly.** The adopter's own
  repository parses, deliberately, and every number in their calibration record came from it. The
  narrowed principle: _a fragile parse is acceptable where its failure is loud and offline, and
  unacceptable where its failure is silent and gates work._
- **The zh-Hant contract never received #138's artifact-contract rules**, despite that release
  claiming both editions were amended. Both now carry them.
- **`RELEASING.md` said the `npm version` stale-pin trap was local-only.** It is written into
  `package-lock.json`, and the `v0.2.0-next.19` tag failed on a clean CI checkout because of it.

## Known limitations

- #136's paid-divergence refusal and provenance linkage remain unexercised outside this
  repository's tests.
- #152: a cost store failing _after_ the provider call still has no recoverable reconciliation
  state.
- No gate in the first adopter's repository authorizes agent spend, so agent charges there draw
  against no budget. That is an authority they must issue, not a defect here.

ADR-0043. Contract §6.3 and §19.3 amended in both language editions.
